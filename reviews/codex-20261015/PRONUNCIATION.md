# 발음기호와 실제 음성의 불일치 — Codex 담당

2026-10-15 KST. 상태: 원인 조사·방안 논의·인수인계. **아직 구현·음원 제작·앱 변경은 하지 않았다.**

## Opus 5.5에게: 작업 분담

**이 발음 문제의 후속 조사와 구현은 Codex가 담당한다.** 영신이 이번 대화에서 직접 지정했다. Opus는 [전수 리뷰](README.md)의 내용·문법·동작 지적을 검토할 수 있으며, 이 발음 건은 중복 구현하지 않는다. 다른 수정 때문에 음성·IPA 공통 코드에 손댈 필요가 있으면 변경 범위를 인수인계에 남겨 충돌을 피한다.

- 기존 리뷰 공유 커밋: `51195f0dae8dda003252cef42f7ce75aac6fc231`.
- 실제 앱 검토 기준: `74a6ddc4d32be73feb86bd7422759c45b9de7fcd`. 위 리뷰 커밋은 앱을 바꾸지 않았다.
- 발음 관련 사용자 제보·Codex 답변·담당 지정의 **대화 원문**: [PRONUNCIATION_CONVERSATION.md](PRONUNCIATION_CONVERSATION.md).
- 이전 전수 리뷰의 `T01`(s/z 전역 동치화로 오자 통과)은 **정답 판정 결함**이다. 이번 `his`의 실제 음성 문제와 별개이므로 혼동하지 않는다.

## 사용자 제보와 확인된 사실

영신은 `his`에 `/hɪz/`가 표시되는데 음성은 `/s/`처럼 들리는 점, 품사에 따라 강세가 달라지는 단어가 대표 발음으로 읽히는 점을 제보했다. 실제 해당 기기 음성은 아직 청취·녹음 분석하지 않았다.

### FABLE

- `buildLessons`는 `ipa`·`pos`를 넘기지만 `speech`는 넘기지 않는다.
- `speak(t)` → `say(t)` → `new SpeechSynthesisUtterance(t.replace(/-/g,""))`. 음성 엔진에는 표제어 철자만 전달된다.
- 카드의 IPA는 시각 효과에만 쓰인다. IPA를 합성 엔진에 전달해 읽히는 구조가 아니다.
- 현재 8,497카드에 `speech` 필드는 없다. 원본에 필드만 더해서는 동작하지 않고 카드 조립·실제 재생 경로까지 연결해야 한다.
- 코드 위치: [buildLessons](https://github.com/esqsoy/vocagoyang/blob/74a6ddc4d32be73feb86bd7422759c45b9de7fcd/vocagoyangfable.html#L2340), [speak / say](https://github.com/esqsoy/vocagoyang/blob/74a6ddc4d32be73feb86bd7422759c45b9de7fcd/vocagoyangfable.html#L2641).

동일 철자를 그대로 음성에 보내지만 현재 카드 IPA가 다른 실제 사례:

| 표제어 | 카드별 발음(현행 데이터의 전사 그대로) |
|---|---|
| contract | 계약 `ˈkɑntrækt` / 수축하다 `kənˈtrækt` |
| record | 기록 `ˈrɛkɚd` / 기록하다 `rɪˈkɔrd` |
| present | 선물 `ˈprɛzənt` / 제시하다 `prɪˈzɛnt` |
| live | 살다 `lɪv` / 생방송의 `laɪv` |
| wind | 바람 `wɪnd` / 감다 `waɪnd` |
| use | 사용 `jus` / 사용하다 `juz` |
| close | 가까운 `kloʊs` / 닫다 `kloʊz` |

같은 표제어에 여러 IPA 문자열이 있는 것은 **121표제어·325카드**다. 전사 관례·장음·분절 차이와 복습 사본도 포함하므로 **발음 오류 121개, 필요한 음원 325개라는 뜻이 아니다.** 필요한 음원 수는 실제 청취와 발음별 중복 제거 후 정한다. 다른 과정에 같은 발음이 나오면 같은 파일을 재사용할 수 있다.

### 마더텅·EBS

- `pronunciationEntry(term, meaning).speech || term`을 읽는 경로가 이미 있다. 실제 예문 전체를 읽는 것이 아니라 별도 발음 데이터의 짧은 텍스트다.
- 마더텅: contract 동사 `to contract`, present 동사 `to present` 등.
- EBS: affect 명사 `flat affect`, primer `a reading primer` 등.
- 원본: [마더텅 발음 자료](../../pipeline/mother-tongue-pronunciations.json), [EBS 발음 자료](../../pipeline/ebs-pronunciations.json), [공통 IPA 안내](../../pipeline/ipa-effects/README.md).
- 문맥으로 발음을 유도하는 방식이며 기기별 발음을 보증하지 않는다. 추가한 `to`나 `a`도 소리로 나온다. **문맥은 주되 그 단어는 들리지 않게 하는 기능이 아니다.**
- 현행 공통 효과 정책은 `speech`와 표제어가 다르면 전체 IPA 표시를 선택한다. FABLE에 연결할 때 기존 글자별 효과를 그대로 유지할 수 있다고 가정하지 않는다.

### his는 별도 확인

- 두 `his` 카드 모두 `hɪz`, 음성 입력은 `his`다. 여기에는 품사별 강세 선택 문제가 없다.
- 사전의 강형은 `/hɪz/`, 약형은 `/ɪz/`다. [Cambridge](https://dictionary.cambridge.org/pronunciation/english/his)
- 영어 어말 `/z/`는 무성화될 수 있다. 성대 진동만이 아니라 앞 모음과 마찰음의 길이·강도 등도 `/s/`와의 대조에 관여한다. 따라서 한국어 '즈'처럼 들리지 않는다는 이유만으로 오류나 잘못된 IPA라고 판단하지 않는다. [흐로닝언대 음성학 교재](https://opentextbooks.rug.nl/americanenglishphonetics2/chapter/11-1-3-lenis-fricatives-final-devoicing/)
- 반대로 사용자의 실제 소리를 확인하지 않고 정상 무성화라고 단정해서도 안 된다. `hiz` 같은 임의 철자로 바꾸면 모든 엔진에서 해결된다는 주장도 하지 않는다.

## 논의 중인 선택지 — 최종 방식 미확정

1. **브라우저 음성 유지 + 일부 문맥 보정.** 품사별 예외를 연결해 시험한다. 용량 추가가 거의 없지만 불필요한 짧은 단어가 함께 들리며, 음성 엔진마다 결과가 달라질 수 있다.
2. **브라우저 음성 유지 + 검증된 예외 발음만 음원.** 정상 단어는 현재처럼 읽고 문제가 있는 발음만 지정 파일을 재생한다. 단어 하나와 IPA 효과를 대응시키기에는 이쪽이 더 확실하다. 단, 녹음 자체의 발음·품질을 검증해야 하고 기본 음성과 목소리가 달라질 수 있다.

브라우저 Web Speech의 일반적인 호출에는 모든 기기에서 IPA 발음을 강제할 수 있는 공통 수단이 없다. SSML 지원은 엔진별로 다르며 지원하지 않는 태그가 무시될 수 있다. SSML·대문자·가짜 철자 변경을 검증 없이 공통 해결책으로 채택하지 않는다. [MDN text](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisUtterance/text), [Web Speech 명세](https://webaudio.github.io/web-speech-api/)

사용자는 이번에 **예외 음원의 용량을 질문하고 Codex 담당을 지정**했다. 음원 도입 전체·코덱·목소리·목록·공개 배포까지 확정한 상태로 기록하지 않는다. 현행 [UI_STANDARD](../../UI_STANDARD.md)의 브라우저 음성 유지 원칙을 이번 문서 공유만으로 변경하지 않았다.

## 예외 음원 용량 계산

계산 가정: **음원 1개 평균 1.0~1.5초, 인코딩 비트레이트 64kbps**. 확정 품질 설정이나 실제 제작 파일의 측정값이 아니다. 짧은 단어 파일의 무음·여백 포함 길이와 실제 평균 비트레이트로 다시 산정한다.

`오디오 데이터 KB = 길이(초) × 비트레이트(kbps) ÷ 8`

십진수 단위(1KB=1,000바이트, 1MB=1,000,000바이트):

| 서로 다른 음원 수 | 64kbps · 1.0~1.5초/개 |
|---:|---:|
| 1개 | 8~12KB |
| 50개 | 0.4~0.6MB |
| 100개 | 0.8~1.2MB |
| 200개 | 1.6~2.4MB |
| 500개 | 4~6MB |

- 파일 헤더·태그·컨테이너·패딩 등은 제외한 오디오 데이터 추정치다. 큰 표지 이미지 같은 부가정보는 필요 없다. 파일별 실제 크기를 더해 최종 보고한다.
- 48kbps라면 위 값의 0.75배, 96kbps라면 1.5배다. 높은 압축률이 `/s/`·`/z/` 같은 마찰음의 학습에 충분한지는 청취로 확인한다. 작은 용량만을 이유로 음질을 확정하지 않는다.
- 표제어 수나 카드 수가 아니라 **재사용을 제외한 서로 다른 발음 파일 수**로 계산한다. 명사·동사가 같은 발음이면 공유하고 발음이 다르면 분리한다.
- 전체 파일을 시작할 때 일괄 다운로드하지 않아도 된다. 현재 exercise에 필요한 예외 파일만 미리 요청하고, 처음 쓰는 파일만 추가 요청하는 설계가 가능하다. `preload="none"`은 힌트이므로 그것만 믿지 말고 `src` 지정/요청 시점을 통제한다. [MDN preload](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/preload)
- 압축 파일 용량과 디코딩 메모리는 다르다. 전체 라이브러리를 한 번에 디코딩·상주시키지 않는다. 내려받은 파일의 캐시는 브라우저 정책에 따라 지워질 수 있다.

따라서 예외가 100~200개라면 **대략 1~3MB 규모를 먼저 검토할 수 있다.** 실제 예외 수는 아직 확정하지 않았다. 전체 10,000단어의 음원 도입과 같은 용량 문제로 볼 필요는 없다.

## Codex의 다음 작업 범위

1. IPA 문자열 차이 중 전사 차이를 걸러 품사·뜻별 실제 다른 발음 목록을 만든다. 잘못된 IPA 자체가 있다면 그 문제와 TTS 선택 오류를 분리한다.
2. contract·record·present·live·wind·use·close와 사용자 제보 his를 우선 비교한다. iPhone Safari와 Chrome 등 실제 음성을 확인한다. 코드만 읽고 청취 검증으로 부르지 않는다.
3. 문맥 보정/예외 음원의 짧은 샘플을 비교해 영신과 방식을 확정한다. 사용권이 확인된 음원이나 제작물을 쓰며 사전 사이트의 음성을 임의로 재배포하지 않는다.
4. 구현 시 세 과정의 정답·따라쓰기·재생·음소거·수동 다음·자동 다음을 함께 검증한다. 재생 실패나 로딩 지연으로 진행이 멈추지 않도록 하고, 음성/효과가 이전 카드에 남지 않게 한다. 대체 재생이 잘못된 발음으로 돌아가는지도 함께 판단한다.
5. 파일 총량·첫 진입 전송량·현재 연습의 추가 전송량과 실제 기기별 결과를 따로 보고한다. 배포 상태는 완료 후 갱신한다.

이번 턴의 검증은 문서의 수치·링크·담당 범위와 앱 소스 불변 확인이다. 새 음원·기기 음성·재생 동작의 검증을 완료한 것으로 취급하지 않는다.
